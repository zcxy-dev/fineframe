# Website (`apps/site`)

The website for fineframe.app: a static, bilingual (English, Traditional Chinese) Next.js export on Cloudflare Pages, with accounts on Supabase and checkout on Paddle. Setup: `README.md`; hosting and service setup: `DEPLOY.md`.

## Commands
- Dev, in this folder: `supabase start`, then `pnpm dev` (port 3000, needs `.env.local` copied from `.env.example`, with the publishable key `supabase status` prints)
- Check before a PR: the repository's checks (root `AGENTS.md`), which lint, typecheck and test this folder too, and `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=local pnpm build` here (`pnpm build` stops unless both are set).

## Release
- A merge to `main` that changes `apps/site/` deploys fineframe.app through Cloudflare Pages' Git integration (its build watch path is `apps/site/*`). It does not wait for CI; the `ci` ruleset check is what keeps a red change from merging. Dependabot updates that change this folder wait for the owner.
- A merge never deploys Supabase (`supabase/migrations`, `supabase/functions`, `supabase/config.toml`) or Paddle changes: `DEPLOY.md` has the steps; ask first.
- Health: no endpoint reports the commit. After a merge, the `Cloudflare Pages` check run on the merge commit must be `success` (`gh api -X GET repos/zcxy-dev/fineframe/commits/main/check-runs`) and `https://fineframe.app/en/` must return 200.
- Preview for user-visible changes: the Cloudflare Pages preview linked from the PR's `Cloudflare Pages` check (public URL).

## Notes
- Previews and production share one Supabase project (the same values are set for Production and Preview, [DEPLOY.md](DEPLOY.md#environment)): sign up only synthetic accounts.
- `public/fonts/` and `app/fonts.generated.css` are generated by `scripts/fonts.ts` on every `pnpm dev` and `pnpm build`; never edit or commit them.
- The Supabase publishable key and project URL in `DEPLOY.md` and `ENTITLEMENT.md` (also the OAuth client id) are public by design, not a leak.
- UI and copy follow [DESIGN.md](DESIGN.md) and [PRODUCT.md](PRODUCT.md) (every product claim must be true of the app's `main`). `ENTITLEMENT.md` is the contract the desktop app in `apps/desktop` implements: a change to the authorize page, `app_config` or `subscriptions` also changes the app, so it is a breaking change: ask first.
- A new font, package, or media file gets a row in this folder's `THIRD_PARTY_NOTICES.md`.
