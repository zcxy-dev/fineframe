# Desktop app

The [web page](../web/README.md) as an app of its own, for people with neither Node nor Python: download the installer, open it, paste a key and make an edit. Installing it is described in the [README](../../README.md#install).

## How it runs

- **Shell:** [Electron](https://www.electronjs.org) 44, whose built-in Node 24 also runs the page's server and `pnpm edit`, as it runs the TypeScript files as they are; nothing else installs Node. The window shows the page from `http://127.0.0.1:<port>`, a port the system hands out at each start, and only that page: other links open in the system's browser.
- **Server:** `next start`, in a process group of its own, with its output in the app's log folder (`~/Library/Logs/Fineframe/server.log` on macOS, `%APPDATA%\Fineframe\logs\` on Windows, `~/.config/Fineframe/logs/` on Linux). It never prints a key.
- **Keys:** in `keys.env` in the app's folder (`~/Library/Application Support/Fineframe/` on macOS, `%APPDATA%\Fineframe\` on Windows, `~/.config/Fineframe/` on Linux), written with permissions 0600 in a folder only its owner can open (on Windows, with an access list that keeps out the machine's other users), not in a repository's `.env`.
- **Account:** making an edit or planning one again, from the page or with `fineframe edit`, needs a signed-in Fineframe account and, once paid plans open, a subscription; rendering, opening earlier projects and downloads do not. It follows the website's entitlement contract (`ENTITLEMENT.md` in the site's repository) in [`lib/account.ts`](../web/lib/account.ts). "Sign in" in the page has the server listen on the first free of `127.0.0.1` ports 47821, 47822 and 47823, and open Supabase Auth's OAuth 2.1 authorization in the system's browser, as a public client with a PKCE challenge, a state and that port's `/callback`; Supabase sends the browser to fineframe.app to sign in, then back with a code, which only the app's verifier turns into a session. The session is kept in `account.json` beside the keys, written the same way, and refreshed before it expires. Before each edit the server reads Supabase's `app_config.billing_enabled`: while it is off, as in the free beta, every signed-in account may edit; once it is on, the account's `subscriptions` row decides: it may edit while the subscription is active, on trial or past due, or cancelled with its paid period not over. With Supabase out of reach, the last check that reached it holds for 7 days. Signing out, in the page's account dialog and the menu ("Sign Out"), deletes the session. The Supabase project's URL, its publishable key and the OAuth client's id, all public, come from the build (`FINEFRAME_SUPABASE_URL`, `FINEFRAME_SUPABASE_PUBLISHABLE_KEY` and `FINEFRAME_OAUTH_CLIENT_ID`, which the stage writes into `supabase.json`); `FINEFRAME_DEV_ENTITLED=1`, for development and CI only, skips the check.
- **Brand kits:** in `brand-kits/` in the app's folder, which the server is given as `VIDEO_EDITOR_BRAND_KITS` ([web page](../web/README.md)).
- **The analysis's Python:** not in the installer. On its first start, the server has the bundled [uv](https://docs.astral.sh/uv/) install a CPython of its own and the worker's locked packages into `python/` in the app's folder ([size](../../README.md#install)), and the page shows the download. uv uses no Python and no settings of the user's own. After an update that changes the worker, it installs the worker again; otherwise later starts only check it.
- **First use:** the models, FFmpeg, ffprobe, Chrome Headless Shell and, for a link, yt-dlp download on the first edit that needs them, each with its bar in the page, into the same caches `pnpm edit` uses (`~/.cache/video-editor/`, `~/.cache/huggingface/`).
- **Speech:** a computer with too little memory for the local speech model ([how much](../../README.md#install)) starts on [cloud speech](../../worker/README.md#cloud-speech), and the page says why and asks for an OpenRouter key.
- **Command line and agent skill:** the menu (the Fineframe menu on macOS, File elsewhere) installs both ([README](../../README.md#use-it-from-an-ai-agent)). "Install Command Line Tool…" writes a launcher, `bin/fineframe` (`bin\fineframe.cmd` on Windows) in the app's folder, which runs the app's own binary as Node on [`src/cli.ts`](src/cli.ts), its arguments passed on as they are, never through a shell; that runs `pnpm edit`'s or `pnpm render`'s script from the app's resources with the environment the server has: uv, the Python environment and the keys saved in the app, which are used over any in the environment. Without the app at the path it names, it says to install or open the app; before the first start has installed the analysis, or after an update that changed it until the app's next start installs it again, it says to open the app once. The launcher is reached by a link in `~/.local/bin` on Linux; on macOS by one in `~/.local/bin` when that is on PATH, or else in `/usr/local/bin`, which every macOS shell has on PATH (`/etc/paths`), made through macOS's administrator prompt only when that folder is not writable; on Windows its folder is added to the user's own Path. At each start, the app writes the launcher again if it points elsewhere, so moving the app or opening a newer AppImage keeps the command working. "Install Agent Skill…" copies [`skills/video-editor`](../../skills/video-editor/SKILL.md) into `~/.claude/skills/video-editor` and `~/.agents/skills/video-editor`, replacing a copy it installed (marked by `.installed-by-fineframe` in it) and asking before replacing anything else; a link there is replaced, never what it points at.
- **Quitting** stops the server and everything it started: an edit, a link's download, the analysis, FFmpeg and the Python setup (on Windows, with `taskkill` on the server's process tree). Closing the window quits. If the app ends any other way, even force-quit, the server sees the pipe from the app close and exits too.
- **Updates** ([`src/updates.ts`](src/updates.ts)): an installed app checks `https://downloads.fineframe.app/` at start and every 4 hours, with [electron-updater](https://www.electron.build/auto-update). On Windows and Linux it downloads a new version in the background, and the page says "Update ready, restart"; it installs when the app restarts from there or quits. The Mac app, not signed with a Developer ID, cannot install one: the page says that a newer version is out, with a link to its DMG, and nothing is downloaded. The keys, the account, the Python environment and the caches stay.

## Why Electron

The editor's planner, renderer and page are TypeScript on Node, and the analysis is Python, so any shell has to carry a Node runtime and a way to install Python. Electron carries Node already and runs the server with it, so the app is one runtime and the shell is TypeScript like the rest of the code. Tauri's own shell is smaller, as it uses the system's web view, but it would still need a Node runtime bundled beside it, a Rust toolchain to build, and on Linux WebKitGTK, which renders the page and plays its video differently from the Chromium it is tested in. Against the 2 GB of Python the first start installs, the difference in size matters little.

## Building

Each installer is built on the system it is for:

```bash
pnpm install
pnpm --filter @video-editor/desktop dist     # dist/Fineframe-<version>-<os>-<arch>.dmg or .AppImage
```

[`scripts/stage.ts`](scripts/stage.ts) builds the page and stages what electron-builder packages into `build/`: the repository's layout with only the packages the server and `pnpm edit` run (pnpm's production install, without symlinks between dependencies), the worker's code and lockfile, and uv pinned by version and SHA-256. Left out: sharp, which neither the page nor a render uses ([notes](../../THIRD_PARTY_NOTICES.md#desktop-installers)). [`electron-builder.yml`](electron-builder.yml) makes a DMG on macOS with Apple silicon (Intel Macs cannot install the analysis: PyTorch and ONNX Runtime publish no builds for them), signed ad hoc as Apple silicon requires but not with a Developer ID; an NSIS installer on Windows, for the user alone and unsigned; and an AppImage on Linux. An NSIS installer keeps no links, and Node runs the workspace's TypeScript packages only through pnpm's links, never from inside `node_modules`, so on Windows the stage lists those links in `links.json` and the app makes them again as junctions on its first start.

`pnpm --filter @video-editor/desktop start` runs the app from the repository, with uv from PATH, after `pnpm --filter @video-editor/web build`.

## Releases

[`.github/workflows/desktop.yml`](../../.github/workflows/desktop.yml) builds the installers on GitHub's Apple silicon macOS, Windows and Linux runners for every pull request that changes the app, the page, the packages or the worker, and runs each built app. A tag `v<version>`, matching `version` in [package.json](package.json), also makes signed build provenance for each installer and uploads the installers, copies of them under names without the version (`Fineframe-mac-arm64.dmg`, `Fineframe-win-x64.exe` and `Fineframe-linux-x86_64.AppImage`, which the website's download page links to), a `SHA256SUMS` of both and the update feed (`latest.yml`, `latest-mac.yml`, `latest-linux.yml` and the blockmaps) to the Cloudflare R2 bucket that `downloads.fineframe.app` serves, with the AWS CLI and the `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` and `R2_BUCKET` secrets; without them the release fails. Nothing goes to GitHub's releases. A tag's build needs the `FINEFRAME_SUPABASE_URL`, `FINEFRAME_SUPABASE_PUBLISHABLE_KEY` and `FINEFRAME_OAUTH_CLIENT_ID` repository variables.

## Tests

`pnpm --filter @video-editor/desktop test` starts the server against a stand-in for Next.js and checks its port, its environment and that stopping it stops what it started.

[`scripts/smoke.ts`](scripts/smoke.ts) runs a built app as a person would the first time, driving its window with Playwright, with the subscription's check off (`FINEFRAME_DEV_ENTITLED=1`): it saves a key, waits while the analysis installs, chooses cloud speech and saves its key, adds a synthetic clip spoken by the system's voice (`say` on macOS, .NET's speech synthesizer on Windows, espeak-ng on Linux), makes a 15 s edit and checks its length and captions, plays it in the window's own player and reads back the frame at its middle, chooses both install items in the menu and checks the skill's files land and that the installed `fineframe` command prints its help and makes a 15 s edit of the clip with the keys saved in the app, then quits and checks that nothing the app started is still running and that the downloads showed in the page. Claude and OpenRouter are local stand-ins (`ANTHROPIC_BASE_URL`, `OPENROUTER_BASE_URL`): the plan keeps every line in order, the graphics are one label with a bundled icon on the first word said clear of any effect, with every line about a graphic printed so one left out says why, every cut passes its check, and each speech chunk is heard as one of the clip's sentences, so it costs nothing. The models, FFmpeg, ffprobe and Chrome Headless Shell download for real, and the clip is analysed, planned, rendered with its graphic and checked. The app's caches and projects, on macOS and Linux its home folder (where the command and the skill install), and on Linux its folder are in a temporary folder of the smoke's own, deleted when it ends, so a local run leaves `~/.cache/video-editor`, `~/.local/bin` and the skills folders as they were; on Windows, where the app does not start with another home folder, the skill goes in the user's own folders, never over a copy the app did not install. CI runs it on every installer; locally, on Linux under a display:

```bash
xvfb-run -a node apps/desktop/scripts/smoke.ts apps/desktop/dist/Fineframe-<version>-linux-x86_64.AppImage --shots shots/
```

`--shots` saves the window at each step.
